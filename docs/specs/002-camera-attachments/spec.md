# Feature Specification: 拍照与本地附件

**Status**: In Progress  
**Priority**: P1  
**Depends on**: 001-local-markdown-notebook

## Platform Scope

本规格同时适用于 Android APK 与 HarmonyOS HAP；相机调用方式可以不同，落盘、
回滚、图片校正和 Markdown 结果必须一致。

## User Stories

### US1 从正文拍照（P1）

用户在每日笔记中点击拍摄，选择拍照或录视频后可以直接插入当前笔记，看到图片预览或视频确认，
且 Markdown 链接和图片已经本地保存。

**Acceptance**: 拍照后强制结束应用，重启仍能在该笔记中打开图片。

### US2 连续记录（P2）

用户可以连续拍摄多张图片，每张图片都按拍摄顺序插入，不需要离开编辑器。

### US3 失败可恢复（P1）

用户取消拍照、存储空间不足或系统相机失败时，原正文不受损且不会产生孤儿文件。

### US4 透视校正（P1）

用户可以通过四个角点调整斜拍的 PPT、白板或纸张，使图片恢复为正面效果后
插入笔记；原始照片同时保留以便追溯。

## Functional Requirements

- **FR-201** 系统必须通过对应平台的系统相机入口完成拍摄，不在应用内重复实现
  完整相机预览和拍摄流程。
- **FR-202** 返回的 URI 必须复制到笔记父目录 `assets/<笔记文件名>/` 后再持久引用；
  文件夹不存在时创建，旧 `attachments/` 内容保持可读。
- **FR-203** Markdown 必须使用相对路径，不能保存临时或设备绝对 URI。
- **FR-204** 成功提示前必须同时完成附件和正文保存。
- **FR-205** 文件扩展名和 MIME 类型必须与真实图片格式一致。
- **FR-206** 用户取消不得显示错误提示。
- **FR-207** 失败或回滚产生的临时文件必须清理。
- **FR-208** 图片处理不得阻塞编辑输入或导致界面长时间无响应。
- **FR-209** 用户必须可以对照片进行矩形裁剪。
- **FR-210** 用户必须可以独立拖动四个角点完成透视校正，并预览校正结果。
- **FR-211** 原始照片和校正后的照片必须同时保存；Markdown 默认引用校正后的
  图片，路径必须是 Vault 内的相对路径。
- **FR-212** 首版支持系统相机原样录制短视频：最长 180 秒、最大 200 MiB，接受有 video
  轨的 MP4/3GP，写入 `-v.{mp4|3gp}` 并插入含尖括号相对路径的普通 Markdown 链接；不承诺
  音频、PDF、OCR、图片标注、媒体库选择、内嵌播放、转码或剪辑能力。
- **FR-213** 笔记随附件 bundle 移动后，后续图片和视频必须写入目标目录同级的 `assets/<note-stem>/`，且生成正确的相对 Markdown 链接。
- **FR-214** 照片处理、附件写入、提交准备和正文提交必须使用原子阶段边界；取消只在正文提交前生效，提交开始后返回明确的“过晚”结果且等待真实完成状态。
- **FR-215** 照片提交前必须校验进入流程时的已保存正文 SHA-256；提交后仅在重读确认链接存在时确认附件、确认链接不存在时回滚，无法确定时保留 marker 与附件供恢复。
