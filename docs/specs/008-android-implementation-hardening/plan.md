# Implementation Plan: Android 客户端实现加固

## Technical Context

- 本规格属于 [`docs/README.md`](../../README.md) 定义的「加固」类，只消除已交付实现与既有规格之间的偏差，不新增能力。
- 范围限于 `android/` 模块，对应规格 `005` 交付的 HarmonyOS 4 Android APK。
- 当前实现为单 `Activity` + 程序化 View + `WebView` 内 `contenteditable` 编辑器，Vault 访问经由 SAF (`DocumentsContract`)。
- `docs/contracts/vault-contract.md` 是文件格式、附件路径与保存事务语义的唯一契约来源。
- `docs/design/note_editor.md` 与 `docs/design/capture_flow.md` 定义用户可见的状态与恢复路径；本规格不改变这些行为，只让实现与之相符。
- `docs/design/components.md` 与 `003-remote-sync` 已要求同步状态离开进度页后仍可发现；
  本规格只加固 Android 现有实现的生命周期，不改变同步算法和数据范围。
- Markdown 渲染在 Kotlin 侧完成，反序列化在 WebView 内的 JavaScript 中完成。两侧共同构成往返链路，缺陷可能出现在任一侧。

## 缺陷归因

| 编号 | 现象 | 根因 |
| --- | --- | --- |
| D1 | 自动保存从不触发 | `postAtTime` 的时间基准是 `SystemClock.uptimeMillis()`，实现误用 `System.currentTimeMillis()` |
| D2 | 用户正文被改写 | 渲染按行 `trim()` 并只识别有限语法，未支持的块级结构在往返中丢失缩进与结构 |
| D3 | 相对链接被绝对化 | 序列化取 DOM 的 `href` 属性，浏览器已将其解析为绝对 URL |
| D4 | 崩溃恢复不完整 | 恢复例程只在打开每日笔记时执行，且只扫描每日笔记目录 |
| D5 | 大目录卡顿 / ANR | 目录枚举与逐篇全文读取在主线程执行，列表为非回收容器 |
| D6 | 内存持续增长 | 每次进入编辑器新建 `WebView`，旧实例未销毁 |
| D7 | 拍照易内存不足 | 预览位图上限为 4096 边长且使用 `ARGB_8888` |
| D8 | 状态丢失 | 未实现实例状态保存与恢复 |
| D9 | 正文被逐层转义 | 序列化时对 DOM 文本再次执行 HTML 转义，`<` 与 `&` 每保存一次多一层实体 |
| D10 | 已有笔记读取失败后显示默认标题并标记“已保存” | 读取接口用 `null` 同时表达读取失败与无内容，编辑器用新建笔记模板兜底 |
| D11 | 旋转后回到文件库，照片处理和滚动上下文丢失 | 页面、文档、临时照片和位置状态只保存在 Activity 字段，未持久化实例状态 |
| D12 | 保存期间继续输入会短暂误报“已保存”，慢速 Vault 会卡住界面 | 保存请求没有内容修订号，且 SAF 读写在主线程执行 |
| D13 | 离开同步进度页后无法查看进度或结果 | 同步状态及结果由页面字段持有，回调只在当前仍为进度页时消费 |
| D14 | JavaScript 序列化超时后旧回调仍可写入，旋转后旧 WebView 无法释放 | 保存屏障只有 URI latch，没有唯一操作身份、终态或超时释放回调 |
| D15 | 旋转后把 Vault 旧正文作为 dirty 恢复并自动保存 | Bundle 只保存修订号，没有与该修订对应的进程内正文快照 |

## 0.1 后续优化事项

当前 Android APK 的 `0.1.0` 基线将以下四类问题作为一个统一的“内容与状态可信”优化
事项推进，避免分别修补后仍留下跨流程断点：

1. **读取安全**：明确区分新建、加载中、读取成功和读取失败，失败时禁止默认内容覆盖。
2. **上下文恢复**：统一保存文件库、编辑器和照片处理页的导航、内容与临时事务状态。
3. **保存可信**：以内容修订号驱动保存状态机，将 Vault I/O 移出主线程并覆盖并发输入。
4. **同步可发现**：同步任务状态脱离页面生命周期，在设置页可重新进入进度与结果。

这四部分共享同一验收门槛：旋转、后台、重建和慢速文档提供方不得造成内容丢失、状态
误报或无法解释的跳转。

## Delivery Phases

1. **可验证性**：建立单元测试工程，使 Markdown 编解码脱离 Android 框架依赖并被测试覆盖。
2. **内容保真**：引入逐字保留的块级结构机制，修正链接序列化，禁止对未编辑笔记的写入。
3. **保存可信**：修正自动保存计时，加固保存状态机，扩大崩溃恢复范围。
4. **资源与性能**：释放 WebView，限制预览解码尺寸，收敛列表读取，将 Vault IO 移出主线程并改用可回收列表。
5. **平台细节**：FileProvider 授权、纯文本粘贴、字体缩放响应、实例状态恢复。
6. **0.1 内容与状态可信优化**：补齐读取失败保护，扩展编辑器/照片上下文恢复，引入
   修订号保存状态机，并将同步进度与结果迁出页面生命周期。
7. **后续性能收敛**：以不可变照片变换快照将裁剪/编码迁出 UI 线程，消除绘制路径的
   手势排除 IPC；随后以可失效搜索索引、可回收列表和常驻页面宿主降低大 Vault 的 SAF、
   分配与重建开销。每步以真实 Vault 基准和 Mate 60 验证，而非只以代码结构作为完成证据。

各阶段顺序不可颠倒：在 D2 修复前让 D1 生效会放大内容被改写的影响面。

## 技术决策

- **逐字保留优先于扩展渲染**：与其为表格、代码块等实现完整的双向编辑，不如将其作为只读的原文块渲染并在序列化时逐字回写。这样既满足 FR-801/FR-802，又不引入新的往返风险；后续如需可编辑再单独立项。
- **编解码去平台化**：将 HTML 转义与附件 URL 生成从 `android.text.TextUtils`、`android.net.Uri` 解耦，改为纯 Kotlin 实现与注入式解析器，以满足 FR-818。
- **脏标记而非内容比对**：以「是否发生过用户编辑」作为写入前置条件，避免每次保存都做全文比对，同时满足 FR-804。
- **令牌化保存与内存恢复**：应用级协调器拥有 `PendingNoteSave` 的唯一操作标识、阶段和截止
  处理；JavaScript 只可向仍处于 `SERIALIZING` 的同一操作提交正文。正文快照仅在进程内保留到
  写入成功、明确放弃或 Vault 切换，Bundle 只保存导航和非正文元数据。

## Constitution Check

- Vault 始终是唯一事实源；本次改动不新增私有正文副本，也不改变附件落盘路径。
- 破坏性行为优先阻断：无法保真的结构宁可只读，也不静默改写用户内容。
- 两端语义一致：Kotlin 侧的保真规则须在 `006` 的 HAP 实现中保持相同结果。
- 不把未经真机验证的平台行为写成结论；受限项记录在任务说明中。

## Risks

逐字保留的块级结构在编辑器中不可直接编辑，可能被用户理解为「内容被锁定」。缓解方式是在设计文档中明确该状态的呈现与说明文案，并在评审清单中作为必查项。

将 Vault IO 移出主线程会引入并发与生命周期问题，可能带来新的崩溃路径。缓解方式是先完成阶段 1 的测试基础设施，再逐个流程迁移，并对每个后台回调做宿主存活检查。

状态恢复不得把正文复制到不透明的长期私有存储。允许使用系统实例状态或短期事务标记
恢复未完成上下文，但已确认保存的正文和附件仍以 Vault 为唯一事实源。

同步状态迁出 Activity 后必须避免重复启动同一任务。实现需使用稳定任务标识和单一状态
来源，并保证取消只响应用户的明确操作，而不是配置变化或页面离开。
