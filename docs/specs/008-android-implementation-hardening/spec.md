# Feature Specification: Android 客户端实现加固

**Status**: In Progress  
**Priority**: P0  
**Depends on**: 001-local-markdown-notebook, 002-camera-attachments, 003-remote-sync, 004-harmony-4-5-compatibility, 005-harmonyos4-android-apk, 007-design-knowledge-base

## Goal

修复 HarmonyOS 4 Android APK 现有实现中会造成用户内容被改写、保存不生效、状态
丢失、界面卡顿与资源泄漏的缺陷，使 Vault 契约与设计原则在真实设备上真正成立。

本规格不新增用户功能，只针对既有实现的正确性、稳定性与性能。

## User Stories

### US1 用 禾记（Heji Notes） 打开笔记不会破坏 Obsidian 里写好的内容（P0）

用户在 Obsidian 中写有代码块、表格、有序列表、嵌套列表、引用和 YAML front matter 的笔记，用 禾记（Heji Notes） 打开、编辑其中一段并保存后，未触及的部分与原文逐字节一致。

**Acceptance**: 含上述结构的样例笔记经「打开 → 编辑首段 → 保存」后，除被编辑段落外的原始文本与缩进保持不变。

### US2 保存状态可信（P0）

用户输入后无需手动操作，正文会在短暂停顿后自动落盘，状态提示与实际写入结果一致。

**Acceptance**: 输入停止约 0.6 秒后状态由「未保存」变为「已保存」，且文件内容确已更新；未编辑的笔记不会被写入。

### US3 大 Vault 仍可流畅浏览（P1）

用户的 Vault 含数百篇笔记时，进入目录、滚动列表和返回上一级不出现明显卡顿或无响应。

**Acceptance**: 单个目录含 200 篇笔记时，进入该目录不触发 ANR，列表滚动不掉帧到不可用程度。

### US4 反复进出编辑器不劣化（P1）

用户在浏览器与编辑器之间往返多次后，应用内存占用保持稳定，不出现闪退。

**Acceptance**: 连续进出编辑器 20 次，不产生持续增长的 WebView 实例。

### US5 中断后可恢复（P1）

拍照写入或笔记保存过程中应用被系统回收，重启后笔记与附件仍处于可解释的一致状态。

**Acceptance**: 任意目录下的中断保存都能在下次启动时被恢复，不仅限于每日笔记目录。

### US6 笔记读取失败不会伪装成空白内容（P0）

用户打开一篇已有笔记时，如果 Vault 临时不可读、授权失效或文档提供方返回错误，应用
不会显示一篇可编辑的默认笔记并声称“已保存”，也不会允许该默认内容覆盖原文件。

**Acceptance**: 模拟已有笔记读取失败后，编辑器不显示默认正文且保存入口不可用；页面
持续说明原文件未被修改，并提供“重试”“重新选择 Vault”和“返回文件库”。

### US7 旋转或重建后仍留在原工作上下文（P1）

用户在子目录、笔记编辑器或照片处理页旋转屏幕，或者 Activity 被系统重建后，仍回到
同一层级、同一笔记或同一张待处理照片，不需要重新寻找内容或重新拍摄。

**Acceptance**: 在文件库、编辑器和照片处理页分别旋转屏幕，路径、滚动位置、未完成
输入、光标/插图位置及可恢复的照片处理上下文保持；无法完整恢复时明确说明并安全返回，
不得产生孤儿临时文件。

### US8 保存状态始终对应最新输入（P0）

用户在一次保存仍进行时继续输入，界面不会因较旧版本写入完成而提前显示“已保存”；
Vault 读写也不会长时间阻塞键盘、滚动或返回操作。

**Acceptance**: 连续输入覆盖至少两个自动保存周期时，只有最新内容成功落盘后才显示
“已保存”；较旧保存完成不会覆盖新内容或把“未保存”误报为“已保存”。

### US9 离开同步页后仍能找到同步状态（P1）

用户启动同步后可以返回设置或文件库，随后仍能看到同步正在进行、重新打开进度，并在
完成、取消、冲突或失败后查看结果摘要。

**Acceptance**: 同步中离开进度页不会静默取消或丢失任务；设置页持续显示当前阶段与
数量，任务结束后保留可重新进入的结果，直至下一次同步替换或用户明确清除。

## Functional Requirements

### 内容保真

- **FR-801** Markdown 往返必须无损：应用不得因渲染或序列化改变用户未编辑的正文，包括缩进、空行数量、块级结构与 `<`、`&` 等字符的原始写法。
- **FR-802** 编辑器无法保真编辑的块级结构（围栏代码块、缩进代码块、表格、有序列表、嵌套列表、引用块、水平线、任务列表、YAML front matter）必须以原文逐字保留并回写。
- **FR-803** 链接必须以原始 Markdown 目标回写，不得被规范化为绝对 URL；相对路径语义以
  [`docs/contracts/vault-contract.md`](../../contracts/vault-contract.md) 为准。
- **FR-804** 未发生用户编辑的笔记不得被写入。

### 保存与恢复

- **FR-805** 自动保存必须在输入停止后按约定延迟真实触发，状态提示必须反映实际写入结果。
- **FR-806** 保存事务的崩溃恢复必须覆盖用户可编辑的全部目录，而不仅是每日笔记目录。
- **FR-807** 保存流程不得因回调未触发而进入永久阻塞状态；并发保存请求的完成回调不得被丢弃。
  每次异步序列化必须有唯一操作标识和截止状态；失效后的晚到回调不得排队写入，旧 WebView
  必须幂等释放。
- **FR-808** 应用必须在配置变化或进程重建后恢复当前所处界面、当前笔记、浏览路径、
  列表滚动位置和可安全恢复的未完成输入。
- **FR-819** 已有笔记读取失败时不得使用默认正文替代、标记为“已保存”或允许覆盖原文件；
  必须显示持续错误状态和可执行的恢复入口。
- **FR-820** 新建笔记的默认正文与已有笔记的读取失败必须使用不同的数据结果和界面状态，
  保存能力只在文档已成功读取或明确创建后启用。
- **FR-821** 保存状态机必须为编辑内容分配单调递增的修订号；只有最新修订成功写入后
  才能显示“已保存”，较旧请求不得覆盖或确认较新的输入。
- **FR-822** 保存失败、离开编辑器或应用进入后台时，最新内存内容与状态必须保留；任何
  会丢弃未保存输入的路径均须提供继续编辑、重试保存和明确放弃的选择。
  已序列化但写入失败的正文可仅在当前进程内恢复；若 dirty 元数据存在但正文快照不存在，必须
  显示恢复错误并允许打开 Vault 已保存版本，禁止以旧 Vault 正文重建 dirty 状态并自动保存。
- **FR-823** 照片处理上下文必须在旋转或可恢复重建后保留待处理文件、所属笔记、插入点、
  阅读位置和处理模式；无法恢复的临时内容必须安全清理并解释影响。

### 性能与资源

- **FR-809** Vault 的目录枚举、正文读取与写入不得阻塞主线程。
- **FR-810** 列表项摘要必须基于有界读取，不得为生成预览而读取整篇笔记。
- **FR-811** 长列表必须使用可回收的列表容器，避免为每个条目常驻视图。
- **FR-812** 编辑器销毁时必须释放 WebView 实例。
- **FR-813** 照片预览解码必须限制在设备显示所需的尺寸内，避免超大位图导致内存不足。
- **FR-814** 后台任务的界面回调必须在宿主已销毁时安全终止。
- **FR-827** 照片确认必须先在 UI 线程冻结裁剪/透视参数；位图变换与 JPEG 编码不得在
  UI 绘制或输入线程执行。处理期间保留取消、失败恢复、附件事务和原光标插入语义。
- **FR-828** 照片处理页不得在 `onDraw` 中更新系统手势排除区域；仅在布局、模式或控制点
  位置实际改变时更新，且相同矩形不得重复提交给系统。

### 平台与工程

- **FR-815** 相机输出 URI 必须通过平台提供的 FileProvider 接口生成并授权。
- **FR-816** 编辑器必须阻止富文本粘贴引入任意 HTML，仅接受纯文本。
- **FR-817** 正文字号必须响应系统字体缩放设置。
- **FR-818** Markdown 编解码逻辑必须可在不依赖 Android 框架的前提下被单元测试覆盖。

### 同步状态体验

- **FR-824** 同步任务及其状态不得由单个进度页面持有；离开页面、旋转或 Activity 重建
  不得导致任务静默取消或结果丢失。
- **FR-825** 设置页必须持续显示未连接、需要重新登录、正在同步、已取消、失败、冲突或
  上次完成时间，并允许重新进入当前进度或最近结果。
- **FR-826** 同步结果摘要必须保留到下一次同步替换或用户明确清除，不能只在完成瞬间显示。

## Out of Scope

- 新增笔记的新建、重命名、删除与搜索能力。
- 目标 SDK 升级、Material Components 迁移与视觉重构（另立规格）。
- HarmonyOS 5/6 HAP 端的对应实现（由 `006` 承担）。
- 新增同步 Provider、改变冲突/删除算法或扩大同步数据范围（由 `003` 承担）；本规格只
  修复 Android 现有同步流程的生命周期和状态可发现性。
