# Quickstart: 同步验收

## Google Drive 配置

1. 按 `android-google-oauth-setup.md` 配置 Google Drive API 和 Android OAuth
   测试客户端；不要在仓库中保存客户端密钥。
2. 在“同步”中选择 Google Drive，完成系统 Google 账号授权。
3. 选择与电脑 Obsidian 对应的 Vault 根目录，确认首次同步范围后再上传。

## NAS 配置

1. 准备威联通 TS-251D 或极空间的远程访问，并分别验证局域网、外网地址。
2. 在“同步”中选择 NAS，填写经验证协议所需的地址、目录和凭据。
3. 确认 Markdown 与照片附件参与同步；`.obsidian/`、本地 `.trash/`、临时文件、索引、
   凭据和同步基线不上传。
4. 确认凭据使用安全存储；同步范围和远端目标在首次上传前明确展示。

## OneDrive 配置

1. 按 `android-onedrive-oauth-setup.md` 注册 Microsoft Entra 公共客户端，并通过 Gradle 属性注入
   client ID 与 Android 签名哈希；仓库不保存客户端密钥。
2. 在“同步”中选择 OneDrive，完成 Microsoft 个人或组织账号授权。
3. 选择或创建 OneDrive Vault 根目录，核对本地 Vault、远端目录和同步范围后开始同步。
4. 验证退出应用后可静默刷新，撤销授权后明确要求重新登录，日志和偏好中无令牌或下载 URL。

## 验收

先运行协议无关的 Provider、规划器、基线编解码、冲突保留和故障注入测试，再构建
当前待验收的平台客户端。随后在两个独立安装实例和测试远端执行：

1. 设备 A 创建含三张照片的笔记并同步到空远端。
2. 设备 B 首次同步，确认 Markdown 和所有相对图片引用可用。
3. A、B 离线修改同一笔记，再依次同步。
4. 确认产生清晰命名的冲突副本，两份内容均未丢失。
5. 在上传大图中途断网并结束应用，恢复网络后重试。
6. 确认远端无半文件，本地内容完整，同步基线未提前更新。
7. 使凭据失效，确认应用要求重新认证且日志不含敏感值。
8. 取消授权与进行中的同步，确认 UI 可恢复且旧基线保持不变。
9. 同步开始后立即返回文件库，打开并保存本地笔记；确认输入与保存不被阻止，设置“同步详情”
   可重新进入，完成或失败会显示系统通知。若通知被关闭，仍可从设置查看最后状态。
10. 在同步扫描后于本地创建同路径笔记；确认原本地文件保留，远端内容另存为冲突副本，且详情显示冲突。
11. 完成一次成功同步后，在同步空闲时将含图片和视频的笔记移到另一普通目录；确认移动过程无需网络，且旧路径不会在文件库中复活。
12. 启动下一次同步，确认目标笔记和全部附件先上传并验证，旧 Drive 文件进入回收站；再次同步不下载旧路径。
13. 分别在目标上传后、旧路径回收前后中断网络或结束应用；恢复后重试，确认无永久删除、无重复冲突副本且基线仅在完整成功后更新。
14. 在电脑 Obsidian 修改旧远端笔记或给旧附件目录添加文件后同步；确认远端内容保留为冲突副本，而非被静默回收。
