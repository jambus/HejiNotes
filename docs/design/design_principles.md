# 禾记（Heji Notes） 设计原则

## 目的与适用范围

本知识库是 禾记（Heji Notes） 两端客户端（HarmonyOS 4 Android APK 与 HarmonyOS 5/6 原生 HAP）的共同体验基线。开发新的用户可见功能前，先查阅相关页面或流程；若行为变化，先更新本文档或对应专题，再更新功能规格、计划和任务。

本文定义体验，不取代数据契约。Markdown、附件路径、事务恢复和冲突规则以
[共享 Vault 契约](../contracts/vault-contract.md) 为准；发生冲突时以该契约为准。

### 外部参考的使用方式

[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) 是本项目的交互质量参考，尤其用于导航层级、上下文保留、反馈和动效判断。吸收原则，不复制 iOS 专有控件、视觉语言或手势；Android APK 和 HAP 仍优先使用各自平台熟悉的系统模式。发生冲突时，依次以 Vault 契约、目标平台可用性和本知识库为准。

## 核心原则

### 1. 文件优先，所有权归用户

用户选择的 Vault 是唯一事实源。界面必须明确操作针对的 Vault 与笔记；正文、图片、回收站和冲突副本不得被隐藏在应用私有空间。不要为了“更方便”而静默创建副本、改名、搬移文件或替换用户内容。

### 2. 记录应当即时，保存应当可信

默认入口是当天每日笔记。常见输入、拍照和插入不应要求多层跳转或重复确认；同时，保存状态必须始终可见且可理解。只有正文和附件都安全写入 Vault 后，才能告知用户“已保存”或“已插入”。

### 3. 先保留，再处理

拍照和编辑是可回溯的记录过程。照片校正不覆盖原图；失败、取消或权限失效不修改已保存正文；需要恢复时提供明确入口和下一步，而非仅显示技术错误。

### 4. 以内容为中心，而非以应用为中心

界面让用户读、写、找和回看 Markdown 内容。工具栏只放当前上下文中的高频动作；低频设置和诊断信息放入二级入口。链接、标签、图片和文件名应保持可读、可复制、可被 Obsidian 等工具理解。

### 5. 跨端行为一致，平台表达自然

两端可以采用各自原生控件、间距与系统导航，但同一操作必须有相同的结果、文案含义、保存时机和错误恢复路径。不要为追求像素一致而牺牲系统可用性，也不能用平台差异改变 Vault 内容。

### 6. 让状态可见，让后果可预期

每项异步操作都要有开始、进行、成功或失败的可见状态。破坏性操作说明影响范围并提供可恢复路径；可逆操作优先提供撤销。不要用瞬时提示替代重要的持续状态。

### 7. 默认可读、可触达

支持系统字体放大、深浅色外观、竖横屏和安全区域。文字、图标和触控目标必须保持清晰且可操作；颜色不是传达状态的唯一方式。

### 8. 导航保留方向与上下文

用户应始终知道自己在 Vault 的哪个层级，以及返回后会到哪里。每次深入内容只进入一个更具体的层级；返回回到刚离开的父层级并保留其滚动位置、筛选和未完成输入。切换顶级区域不等于执行操作，执行当前内容的动作放在工具栏或上下文操作区。

### 9. 动效解释变化，而非装饰变化

动效只能用于说明状态变化、维持空间关系、确认直接操作或减轻等待感。它应简短、可打断、紧随用户手势，并且不能阻塞下一步。频繁输入、保存和列表滚动默认不添加引人注意的自定义动效；动效绝不是传达状态的唯一方式，必须尊重系统的“减少动态效果”偏好。

## 设计决策顺序

遇到取舍时，按以下顺序决定：

1. 内容是否仍以正确、可迁移的 Markdown 和相对附件链接留在 Vault？
2. 用户能否理解当前状态、取消操作并在失败后恢复？
3. 现场记录是否仍然足够快速？
4. 两端是否保持相同的结果与关键语义？
5. 视觉是否与当前页面和平台协调？
6. 导航或动效是否让用户更清楚内容、方向或操作结果？若否，移除它。

## 文案与反馈

- 使用直接动作词：`保存`、`重新选择 Vault`、`保留并重试`，避免含糊的“确定”。
- 成功消息说明完成的事，例如“照片已插入每日笔记”；失败消息说明影响和下一步。
- 用户取消系统相机或选择器是正常结果，不显示错误提示。
- 不在面向用户的文案中暴露 URI、堆栈或绝对路径；诊断信息可在开发日志中保留并脱敏。
- 中文与 English 是同等完整的应用呈现语言。语言选择是应用偏好，不写入 Vault；切换后立即
  重绘当前界面并在重启后恢复。Android 默认跟随系统（非中文回退 English），HAP 默认中文，
  两端均可由用户明确选择中文或 English。同步、保存和错误状态保存语义代码/计数而不是渲染后的
  文案，以便始终按当前语言显示。

## 维护规则

- 每个新页面或流程至少关联一项功能规格和本目录的一篇文档。
- 平台受限导致的例外，必须记录受影响平台、用户影响、临时交互和补齐条件。
- 评审前使用 [设计评审清单](review_checklist.md)；已接受的例外同样需要记录。
