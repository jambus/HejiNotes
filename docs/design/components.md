# 禾记（Heji Notes） 组件规范

## 共通规则

组件描述的是语义与状态，不规定具体框架。Android APK 与 HAP 可采用不同原生实现，但名称、结果、禁用条件和反馈必须一致。所有可点击区域应有清晰标签、可见焦点或按压反馈，并满足至少 44 × 44 dp 的触控目标（空间受限的图标操作通过增加热区满足）。

颜色必须同时搭配图标、文字或形状传达状态；正文、控件和图片边界需在深浅色与字体放大时保持可辨认。动态状态须能被辅助技术读出。

## 应用骨架

### 应用图标

禾记（Heji Notes）的应用图标以“从笔记中生长”为核心：深林绿色圆角底上放置一本打开的暖白色笔记本，一株三叶树苗从中缝向上生长。笔记本表达可读、可迁移的 Markdown 记录，树苗表达持续积累与回看；图标不包含文字、字母、状态或装饰性星光。

- Android APK 与 HAP 使用同一构图、颜色语义和留白比例；平台可采用各自的 SVG/Vector 格式，但不能替换为不相关的图片。
- 在小尺寸下优先保留书脊、左右页轮廓、树干和三片叶子的可辨识形状；不依赖细小正文线、渐变或颜色单独表达含义。
- 深林绿底、暖白页面和嫩绿叶片在深浅系统表面上均应有清晰边界；图标本身不承担交互状态或辅助技术标签。

### 导航层级

禾记（Heji Notes） 的信息层级为 `Vault → 文件夹或笔记列表 → 笔记编辑器 → 图片处理`。根页面显示当前 Vault；打开文件夹或笔记属于向下进入，返回应逐层回到上一个可理解的上下文，不应突然跳回根页面。

- 顶级区域用于切换不同信息域（例如“笔记”“搜索”“设置”），只承担导航，不承载“新建”“拍照”等动作。Android 文件库顶部保留“搜索笔记”和“更多选项”两个带辅助标签的图标操作；“设置”“切换 Vault”等低频文字操作置于更多菜单。
- 文件夹、搜索结果和笔记列表应保留各自的滚动位置、筛选词与选择状态；返回或关闭处理页不得重置这些状态。
- 模态页面只用于必须先完成、确认或取消的短流程，例如图片处理或放弃未保存改动；关闭后回到启动它的同一位置。
- 系统返回手势或返回按钮始终优先返回上一层；有未保存内容时先进入明确的保存/放弃决策，不能直接丢失。

### 手机 Vault 文件库布局

Android APK 的启动页是 Vault 文件库，不是空白编辑器。它采用“工具在边缘、内容在中心”的笔记应用布局：顶部识别当前 Vault，主体依次列文件夹、当前目录的 Markdown 笔记和其他文件，底部保留一个明确的“今日笔记”主入口。

```text
┌──────────────────────────────────────────────┐
│ 禾记（Heji Notes）                         切换 Vault  │
│ 当前 Vault 名称 / 当前目录路径                 │
├──────────────────────────────────────────────┤
│ 文件夹                                         │
│  ▸ Daily Notes                                 │
│  ▸ Projects                                    │
│                                                │
│ 笔记                                           │
│  2026-07-30                          内容摘要 │
│  会议记录                              内容摘要 │
├──────────────────────────────────────────────┤
│           新建              打开今日笔记        │
└──────────────────────────────────────────────┘
```

- 根目录显示 Vault 名称；进入文件夹后显示可读路径。`.obsidian`、`.markbook`、`.trash` 和临时文件不显示在主文件库。`assets` 与 `attachments` 显示为只读附件目录，可逐层进入；其中图片、视频及其他附件显示文件名、类型和可用大小，并交给系统查看器打开。附件目录和附件文件不提供新建、重命名、移动到回收站或左滑操作，避免绕过笔记附件事务破坏 Markdown 引用。
- 文件夹与笔记各自使用一个连续的分组容器：容器内条目以细分隔线区分，不把每一行都做成独立卡片。分组的首尾保留圆角，空状态仍使用独立说明卡；这样列表保持可扫描，同时“打开今日笔记”仍是页面唯一醒目的主操作。
- 文件夹、笔记、进入下一层和设置状态使用同一套平台原生语义化图标；装饰图标不单独获得辅助技术焦点。行的辅助标签应包含类型、名称与有用摘要，不能仅朗读图标或符号。
- 普通文件夹排在笔记前，其他文件排在笔记后；笔记显示文件名和首段摘要。主文件库中的每个普通笔记或普通文件夹可左滑显示右侧“重命名”和“删除”两个文字明确、颜色不同且触控区域至少为 44 × 44 dp 的操作块；滑动只显示操作，不能直接删除。展开一行后，点击其前景、相邻条目、页面其他区域或返回先收起；长按仍打开同一操作菜单，并为辅助技术提供“重命名 <名称>”和“移到回收站 <名称>”入口。附件目录、附件文件、每日笔记目录与 Drive 文件夹选择器不使用该左滑操作。删除先确认，再整体移入 Vault 根目录 `.trash/`，不在列表中提供不可恢复删除。说明中的相对 Markdown 链接不因移动或重命名而改写，附件不自动清理。
- 笔记行同时显示内容摘要、可用的相对修改时间；当笔记真实相对路径等于已配置每日目录下当天文件时，显示“今日笔记”。时间不可用或异常时省略，不能显示 Unix 纪元日期；时间、每日状态、标题和摘要均由辅助技术读出。
- 第一次出现可左滑的普通条目时，在分组上方显示可关闭的行内提示：“左滑条目可重命名或移到回收站；长按也可操作。”提示关闭或显示后都只记录在应用偏好中，不写入 Vault；它应能被辅助技术读出，不能依赖瞬时 Snackbar 或演示动画。
- 非空文件夹只能由底层 Provider 整体移动到 `.trash/`；若 Provider 不支持或移动失败，保留源目录及全部内容，并显示可恢复的错误。不得通过递归复制后删除模拟移动。
- 移到回收站的确认后反馈依次说明“等待前序文件操作”“正在移到回收站”和“正在刷新列表”；阶段文字须可由辅助技术读出。确认 Provider 成功后，当前列表立即移除该条目并保留滚动位置，目录复核在后台完成；复核失败不得把成功结果改写为失败，但应在页面显示可重试的刷新提示。
- 底部“打开今日笔记”始终是唯一主操作；相邻的“新建”为次操作，打开“新建笔记”和“新建文件夹”。新建成功后笔记立即进入编辑器，文件夹进入该文件夹。创建、重命名均在同一行显示命名错误，提交期间禁用重复提交。
- 同一目录的笔记和文件夹共享名称空间。创建或重命名前按 NFC 与不区分大小写比较名称；冲突、非法名称或 Provider 改写名称均须明确显示结果，绝不覆盖已有条目。
- 没有 Vault 时显示产品用途和一个“选择 Vault”主操作，不显示不可用的编辑器或拍照操作。
- 文件库不是桌面侧边栏的缩小复制：手机纵向空间中，目录与笔记列表共享一张可滚动页面；横屏时可由平台实现扩展为双栏。

### 设置页面

设置从文件库顶部栏进入，属于顶级配置页面；返回后回到原文件库位置。
设置分组固定按 `同步 → 每日笔记 → 存储 → 显示 → 语言 → 关于` 排列，让最常用的跨设备入口
始终处于首位。
设置分组标题只显示名称，不显示项目数量；文件库中的“文件夹”“笔记”等内容分组才显示实际数量。

- **显示模式**：提供“日间模式”和“夜间模式”两个互斥选项。选择后立即应用到文件库、设置与编辑器，并在重启后保持；不使用颜色作为“已选中”的唯一提示，须同时显示文字状态或勾选。
- **今日笔记目录**：显示当前 Vault 相对路径；点击后进入仅显示文件夹的选择器。用户点“使用此目录”才提交，返回或取消不改变设置。根目录可选，默认是 `Daily Notes`。
- **回收站**：位于“存储”分组，持续显示 `.trash/` 中的项目数或“回收站为空”，始终可进入查看。
  页面仅列出当前 Vault 根目录 `.trash/` 的直接项目；Markdown 可进入“来自回收站 · 只读”查看器，文件夹与其他文件不可继续浏览。单项“永久删除”及页面内“清空回收站（N）”均需明确不可撤销确认，说明文件夹内容、附件保留和 Markdown 链接不改写。确认后只删除当时快照中的直接项目；部分失败保留项目、刷新列表并提供重新确认的重试入口。
- **语言**：设置页提供“跟随系统”（Android）、“中文”和 “English”三个互斥的应用呈现选项；
  HAP 提供“中文”和 “English”。选择后立即应用并在重启后保持，Android 的跟随系统在非中文
  系统上回退 English，HAP 的首次默认值为中文。当前项用“已启用 / Enabled”标识；两项语言都
  必须完整可用，不能显示过期的“即将支持”状态。语言改变只影响应用呈现，绝不改写 Vault 内容、
  Markdown、相对链接、同步目标或保存时机；`Daily Notes`、`.trash`、`assets`、`.markbook`、
  文件名、Provider 名称及持久 Markdown 标记保持原样。
- **关于**：显示应用版本号和构建号，供问题反馈与 APK 升级核对；不得展示用户账号、
  Vault URI、令牌或其他隐私数据。
- 设置不得修改、移动或复制 Vault 内容。目录配置只决定后续打开或创建每日笔记的位置；路径变化后，附件链接必须从笔记所在目录重新计算相对路径。
- 除用户明确确认“永久删除”的清空回收站操作外，设置不得删除 Vault 内容。

### 远端同步

Google Drive 是 Android APK 的首个远端目标，入口位于“设置”的“同步”分组，
而不是隐藏在笔记编辑器中。设置行须持续显示 `未连接`、已选择的 Drive 文件夹、
`需要重新登录` 或上次完成时间，让用户知道操作会影响哪个远端 Vault。

- 首次连接依次进入 Google 系统账号授权、Drive 文件夹选择和范围确认；确认页明确
  显示本地 Vault 名称、远端文件夹名称和“比较并同步”操作。取消不修改本地或远端。
- 文件夹选择器允许在当前 Drive 目录创建新文件夹；创建成功后自动进入该目录，用户仍须
  点“使用此目录”才会把它设为同步目标。创建失败时保留当前位置并显示重试路径。
- 同步由独立于页面生命周期的后台任务执行。启动后用户可立即回到文件库、打开或编辑
  本地笔记；编辑器的保存状态和输入不得因同步页面、进度更新或通知而中断。
- 同步中显示阶段、已处理数量和取消入口；用户仍可返回文件库，并可从“同步详情”重新
  找到当前任务。完成、冲突、取消和失败都要发出系统通知，并在同步详情保留可阅读的
  时间、目标、摘要与最多五项失败文件，不能只显示短暂提示。
- 同一时间每个 Vault 只运行一个远端同步任务；再次请求应明确显示现有任务并进入其详情。
  设备重启或进程被系统终止后，详情必须保留最后已知状态；若任务未能继续运行，应明确
  标记为“已中断，需要重试”，不得误报完成。
- 后续同步方式复用同一任务状态、通知与详情语义；它们只能改变远端授权和传输实现，
  不能把凭据、传输缓存或同步记录写入 Vault。
- 同一路径同时有不同内容时，保留两份并说明冲突副本位置；网络或授权失败不得被呈现
  为远端为空，也不得回退到应用私有目录。
- Vault 顶层 `.trash/` 是手机端的本地删除区，不上传、下载或作为远端删除依据。

### 顶部栏

**用途**：显示当前上下文与页面级操作。

- 左侧：返回上级，或在根页面显示 Vault/导航入口。
- 中间：当前笔记标题或页面名称；标题过长省略，但可在详情或辅助标签中完整读取。
- 右侧：最多放两项最高频、与当前页面直接相关的操作。编辑器中为“拍摄”和“保存”；“拍摄”明确选择拍照或录视频。
- 滚动内容不能遮挡顶部栏；遵守系统状态栏与横屏安全区域。
- 编辑器可将笔记位置与保存状态合并为顶部栏下的一行紧凑元数据。必须持续提供 `未保存`、`正在保存…`、`已保存` 或 `保存失败`；失败时扩展为带下一步的持续提示，不能因紧凑布局而截断恢复路径。完整 Vault/目录/文件名须可由辅助技术读取。
- 状态元数据不重复显示已在标题栏可见的文件名，常态下显示“状态 · Vault · 相对父目录”；标题与状态共同提供完整上下文。

### 底部操作区

**用途**：承载编辑场景中的次要或多步骤操作。

- 不与系统导航手势冲突；出现键盘时仍保留当前输入位置可见。
- 有未完成的图片处理或视频确认时，优先显示“取消”“重新录制”“重试”“插入”等下一步，而不是全局功能。

### Markdown 格式工具栏

编辑器底部的格式工具栏承载撤销、重做、标题、加粗、斜体、标签、链接和表格等上下文操作。
它以连续图标胶囊呈现，包含撤销、重做、标题、加粗、斜体、标签、链接和表格；不使用功能
文字作为按钮标签。窄屏时横向滚动，不压缩正文或 44 dp 触控目标；每个图标提供长按提示和
可访问名称。标题、标签和链接等需要输入或选择的操作，先打开短暂对话框；取消后不影响正文或选区。

- 标题、加粗、斜体随当前光标或选区显示可见选中态及辅助状态；撤销、重做在无可执行历史时禁用。标签、链接、表格仍是一次性操作，不伪装为持续选中。

### 搜索

搜索只读扫描当前 Vault 的普通 Markdown 笔记，匹配文件名、正文与 `#标签`；不创建索引、数据库或 Vault 文件。使用 NFC 与不区分大小写匹配，保持中文子串搜索。文件名优先于标签与正文，结果显示标题、父目录、匹配摘要、每日状态和可用修改时间。

- 输入为空、扫描中、无结果、部分文件无法读取、Vault 无法读取必须分别说明；部分失败不能显示为“无结果”。
- 打开结果后返回搜索，恢复搜索词、结果、滚动位置和焦点；关闭搜索回到原文件库目录与位置。搜索结果只允许打开，不能通过左滑删除或重命名。

### 转场与动效

动效遵循“变化有来源、有去向”的原则：从列表进入笔记时让标题和内容层级保持连续；打开图片处理时让用户理解正在处理哪一张图片；完成或取消后回到原上下文。

- 优先使用系统组件自带的微妙反馈；自定义动效必须服务于状态、反馈或方向，不能仅为装饰。
- 动效应短、可中断且不阻塞触控、输入、返回或重试。用户再次操作时，立即响应而不是等待前一段动效结束。
- 保存、自动保存、普通列表刷新和连续输入不使用显著运动；用保存状态、进度和内容变化传达结果。
- 支持系统“减少动态效果”设置：减少位移、缩放和视差，保留非动态的状态文字、图标或进度反馈。

## 操作组件

### 主操作按钮

**适用**：一个页面或步骤中最重要且安全的下一步，如“选择 Vault”“插入照片”。

- 同一视觉区域只允许一个主操作；文字描述结果，不用“确定”。
- 执行中禁用重复触发，并显示进行状态；不阻塞阅读或编辑输入，除非当前步骤必须完成。
- 出错后恢复可用状态，保留用户输入，并提供明确的重试或替代操作。

### 次要按钮与图标按钮

**适用**：保存、返回、裁剪、旋转、删除等已知动作。

- 图标按钮必须有可访问名称；不使用没有标签的抽象图标表达关键操作。
- 删除、丢弃和覆盖为破坏性操作，使用明确文字及二次确认；如果可以，优先提供撤销。
- “取消”只放弃尚未提交的当前步骤，不得回滚已安全保存的笔记内容。

### 菜单与溢出操作

**适用**：设置、诊断、低频编辑功能。

- 菜单项用动词开头并按风险排序；破坏性操作与普通操作分组或隔开。
- 关闭菜单不产生副作用；菜单项不可用时给出原因或隐藏，不显示无响应入口。

## 信息与状态组件

### 保存状态

编辑器顶部或靠近标题处持续显示以下之一：

| 状态 | 触发 | 用户可见内容 | 行为 |
| --- | --- | --- | --- |
| 已保存 | 正文已写入 Vault | `已保存` | 可继续编辑 |
| 正在保存 | 防抖保存或手动保存进行中 | `正在保存…` | 防止重复手动保存 |
| 有未保存更改 | 编辑后、保存尚未开始或失败 | `未保存` | 保留内容并可手动保存 |
| 保存失败 | 写入或授权失败 | `保存失败` + 下一步 | 不清空编辑内容；可重试或重新授权 |

不可仅靠短暂 Toast 表示保存是否成功。

### 视觉令牌与反馈

- Android APK 以一套语义化日间/夜间令牌表达主色、主色文字、页面/分组表面、正文/次级文字、分隔线、链接、焦点/按压态与系统栏；应用内按钮、系统主题、编辑器 HTML 和对话框不得各自使用不一致的强调色。
- 每组颜色均通过对比度检查，尤其夜间浅色主按钮必须使用可读的深色文字；颜色不是传达状态的唯一方式。

### 横幅与行内提示

**适用**：影响当前内容但不需要中断的状态，如 Vault 权限失效、冲突副本或索引重建。

- 放在受影响内容附近，说明影响、原因（可理解时）和主操作。
- 权限失效：提示当前 Vault 不可访问，主操作为“重新选择 Vault”；不自动新建 Vault。
- 冲突：说明原内容未被覆盖，并提供查看两个版本的位置。
- 用户主动关闭后，若状态仍存在，在合适位置保留可重新发现的入口。

### Snackbar / 轻提示

**适用**：不影响后续操作的短暂成功反馈，如“已插入照片”。

- 重要结果必须也能从页面状态或内容中验证。
- 若操作可撤销，提供单个清晰的“撤销”动作，并说明撤销范围。
- 系统相机或文件选择器的取消不显示轻提示。

### 加载、空与错误状态

| 场景 | 必须包含 | 禁止 |
| --- | --- | --- |
| 加载 | 正在进行的对象或骨架；超过短暂等待时给出文字 | 空白页面或无限转圈无说明 |
| 空 | 原因、用户价值和一个下一步 | 将空状态误写成错误 |
| 错误 | 影响、可行下一步、保留内容的说明 | 只展示“发生错误”或技术异常 |
| 无权限 | 所缺权限与重新授权入口 | 静默降级到私有目录 |

文件库无法读取当前 Vault 或当前目录时，不能将其呈现为空目录；保留已知 Vault 名称，并显示“无法读取当前 Vault/目录”及“重新选择 Vault”或“返回上一级”的恢复入口。

## 内容组件

### 笔记列表项

显示标题（或首行替代）、相对日期/修改时间和必要的内容摘要。长按或菜单中的删除进入回收站，不做立即永久删除。空标题使用“未命名笔记”仅作为显示标签，不自动改名。

### 文件库创建、重命名与回收站

- 新建笔记接受不带扩展名或一个 `.md` 扩展名的名称，保存时统一使用一个小写 `.md`；新建文件夹不附加扩展名。中文与 emoji 可以使用。
- 拒绝空名称、仅 `.`/`..`、首尾空白、尾点、控制字符、点开头、路径分隔符或系统保留字符、Windows 保留名，以及 UTF-8 编码超过 240 字节的名称。错误在输入框附近持续可见，不能只用轻提示。
- 重命名成功后保留用户所在目录和滚动位置；若 Provider 返回的实际名称不同于请求名称，明确显示“已保存为 <实际名称>”。
- 普通笔记的长按菜单可提供“移动到…”。目标选择器只显示同一 Vault 的普通目录；确认页同时显示目标笔记和 `目标/assets/<笔记名>/`，说明会更新该笔记的本地附件链接、不会更新其他笔记指向它的链接。附件被其他笔记使用、任一笔记无法读取或目标冲突时不开始移动；仅当同一 Vault 的同步正在运行时因结构变更租约而暂时禁用，已配置但空闲的同步不影响本地移动。
- “移动到…”使用层级目录选择器而非扁平路径列表：顶部持续显示 `Vault 根目录 / …` 面包屑；点击文件夹进入下一层，“上一级”仅在非根目录显示；底部“选择此目录”明确提交目标。当前笔记所在目录不可作为目标；根目录可选。选择器仅显示普通目录、保留取消入口，并以连续分组、文件夹图标、进入箭头和至少 44 dp 的触控区域表达层级。
- 移到回收站的确认框必须写明目标是 Vault 根目录 `.trash/`，且说明链接不更新、附件不会自动删除；取消不修改 Vault。移除当前每日笔记目录本身或其祖先时，后续每日笔记目录重置为 Vault 根目录，并在文件库持续显示该提示。

### Markdown 正文与图片

- 正文优先连续阅读和输入；列表、链接、标签和 `[[双向链接]]` 的显示必须保留其 Markdown 语义与可编辑性。
- 图片应保留原始宽高比，加载中使用稳定的占位区域，加载失败显示相对路径与重试入口。
- 点击图片进入查看或编辑上下文，不应破坏正文选择与光标位置。

### 表单与选择器

标签始终可见，错误靠近字段并描述修复方法。调用系统 Vault 选择器或相机前，先在应用内说明目的；系统界面取消返回后保持原页面与编辑内容。
