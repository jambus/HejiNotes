# Markdown 编辑器交互规范

## 目标与边界

编辑器服务于快速记录和可靠保存：用户编辑的是当前 Vault 内的 UTF-8 `.md` 文件，不是应用私有副本。它以所见即所得方式呈现常用 Markdown，但不得改变原有文件名、目录、相对链接或用户未触发的 Markdown 结构。

数据规则以 [本地笔记规格](../specs/001-local-markdown-notebook/spec.md) 和
[共享 Vault 契约](../contracts/vault-contract.md) 为准。

## 页面结构

```text
┌──────────────────────────────────────────────┐
│ 返回 / Vault     笔记标题          拍摄  保存 │
├──────────────────────────────────────────────┤
│ 保存状态 / 权限或冲突横幅（仅在需要时出现）   │
├──────────────────────────────────────────────┤
│                                              │
│               可滚动 Markdown 正文            │
│                                              │
├──────────────────────────────────────────────┤
│ 上下文格式工具（可选；不遮挡输入与键盘）       │
└──────────────────────────────────────────────┘
```

标题区域显示文件的可读名称；空标题或无 H1 时可显示“未命名笔记”，但不得借此自动重命名文件。Vault、相对目录与保存状态可在标题下以一行紧凑元数据呈现，文件名不重复显示；保存失败时该行扩展为持续的恢复提示。正文是页面焦点，键盘、图片加载或状态提示不能导致光标跳到文首。

## 导航与转场

- 从列表打开笔记时，保留用户对“正在打开此笔记”的方向感；编辑器返回后，列表恢复原滚动位置、筛选和焦点。
- 返回手势/按钮的默认目标是上一级列表。只有存在未保存更改、正在插入照片或发生无法安全离开的错误时，才在当前页面给出继续、重试或放弃的明确选择。
- 编辑器内不使用抢眼的页面入场、光标跳动或保存动画。图片插入可用一次轻微、可跳过的内容更新反馈，但完成状态仍由链接和“已插入”文字明确说明。

## 打开与创建

1. 已授权 Vault 打开后，默认进入配置的当天每日笔记；不存在则创建对应 `.md` 文件。
2. 打开已有笔记时，先显示可阅读内容或骨架，再进入可编辑状态；不得先显示空编辑器。
3. Vault 授权失效时，保留最后已显示的内容和未保存输入（若有），显示权限横幅，并引导“重新选择 Vault”。不得创建替代 Vault 或把正文转存到私有目录。
4. 无笔记时，说明可创建每日笔记或浏览 Vault；不要把空 Vault 视为错误。
5. 从任意普通目录创建的笔记必须在创建成功后立即打开；编辑器标题与保存、拍照上下文均基于该笔记的真实 Vault 相对父目录，而不是假定其位于 Vault 根或每日目录。
6. 笔记在文件库中重命名或移到回收站时不得处于编辑状态；若当前笔记已被外部移动或无法再读取，保留内存中的未保存输入并显示可返回文件库或重新选择 Vault 的恢复路径。

## 编辑与 Markdown 行为

- 输入应尽量直接反映到所见即所得内容；常用段落、标题、列表、链接、图片、`#标签` 和 `[[双向链接]]` 均可读、可编辑。
- 光标、选区、滚动位置和正在输入的组合文本优先级最高。自动格式化不得吞字符、破坏输入法组合状态或在用户未完成输入时重排段落。
- 只有用户明确触发的格式操作才改变结构。粘贴、撤销、图片插入与链接编辑都应在光标或选区处发生，完成后让用户继续从原位置输入。
- 无法完整所见即所得呈现的 Markdown 保留原语法并允许编辑，绝不删除或静默改写。
- 呈现层以清晰的标题节奏、段落/列表间距、可辨链接样式、图片留白和等宽原始 Markdown 块提升阅读性；只改变 CSS 与视觉层级，不得把未支持语法转为可编辑 DOM，亦不得改变序列化、光标、选区、输入法组合文本或未触碰内容的往返结果。

## 常用 Markdown 工具

编辑器底部提供水平可滚动的上下文工具栏，不挤占顶部“拍照”“保存”。它包含撤销、
重做、标题、加粗、斜体、标签、链接与表格，所有操作优先作用于当前选区；没有选区时作用于
当前光标位置，并把光标保留在新内容后继续输入。

工具栏采用连续的图标胶囊按钮，图标顺序为撤销、重做、标题、加粗、斜体、标签、链接和
表格；不使用“撤销”“表格”等文字按钮。每个图标提供长按提示和可访问名称。

- **撤销 / 重做**：只作用于当前笔记的编辑器历史，不读取或回滚 Vault 中已保存的其他文件。
- **加粗**：对选区切换 `**粗体**`；空选区进入加粗输入状态。
- **斜体**：对选区切换 `*斜体*`；空选区进入斜体输入状态。
- **标题**：可选择正文或 H1 至 H5，生成相应的 Markdown 标题层级。
- **标签**：要求输入标签名后插入 `#标签`；不允许空标签或路径分隔符。
- **链接**：要求输入 URL；有选区时将选区作为链接文字，无选区时插入可编辑的链接文字。
- **表格**：在光标处插入标准 Markdown 表头、分隔行和一行示例内容。表格在下次打开时可
  以原始 Markdown 保留块显示，不得因工具栏操作丢失列分隔符。

操作导致的内容变化与普通输入一样立即进入“未保存”并使用
自动保存；格式菜单取消或标签/链接输入取消不修改正文。

光标、选区、格式化、撤销和重做后，标题、加粗和斜体操作应立即刷新其选中态，撤销/重做应刷新可用态；该视觉反馈不得移动光标、选区或输入法组合文本。

## 保存模型

1. 每次内容变更立即标记为“未保存”。
2. 用户停止连续输入约 600 ms 后开始自动保存；连续输入期间不反复抢占界面。
3. 顶部“保存”随时可触发立即保存，并显示“正在保存…”。
4. 写入完成后才显示“已保存”；写入失败时仍保留全部内存中的编辑内容，并显示“保存失败”及可行动作。
5. 离开页面、进入拍照流程、应用转到后台或即将退出时，尝试提交最新内容；若不能提交，明确阻止会导致未保存内容消失的离开操作，或提供“继续编辑”“重试”“放弃未保存更改”三选项。最后一项须说明只放弃本次未保存修改。

每次 WebView 序列化必须属于唯一保存操作，并按
`SERIALIZING → WRITE_QUEUED → WRITING → SAVED | WRITE_FAILED` 推进。序列化失败进入
`SERIALIZE_FAILED`，超过截止时间进入 `EXPIRED`；后到的 JavaScript 回调不得重新激活或写入已
失效操作，旧 WebView 只释放一次。已取得的正文快照只在进程内保留：写入失败时用于旋转后逐字
恢复并维持“保存失败”，成功、明确放弃或切换 Vault 时清除，不写入 Bundle、偏好、数据库或私有
正文缓存。若实例状态称有未保存修改但进程内快照已不存在，必须显示明确恢复错误以及“打开 Vault
中已保存版本”“返回文件库”，不得把旧 Vault 正文标为未保存后自动写回。

## 保存失败、外部变化与冲突

| 情况 | 编辑器行为 | 用户操作 |
| --- | --- | --- |
| 临时写入失败 | 保留编辑内容与“未保存”状态 | 重试保存 |
| Vault 权限失效 | 停止写入，不覆盖原文件 | 重新选择 Vault |
| 存储空间不足 | 不清空内容；显示空间不足 | 清理空间后重试 |
| 外部文件变化且可安全重新载入 | 说明已更新并保留未保存内容 | 查看更新 / 合并后保存 |
| 同一路径两端都修改 | 不静默覆盖；按 Vault 契约保留冲突副本 | 查看冲突版本 |

“保存失败”不能用短暂提示后消失；在恢复前持续可见。

## 图片与视频插入

“拍摄”入口位于编辑器顶部栏，先明确选择拍照或录视频。用户完成图片处理并确认插入后：先完成原图、校正图（如有）及 Markdown 事务，再在当前光标处插入相对路径图片链接。视频录制返回确认页后，原样保存并在光标处插入普通 Markdown 视频链接。随后将光标置于链接后，方便继续记录。取消或失败保持正文、光标和滚动位置不变。详细步骤见 [拍照流程](capture_flow.md)。

对于任意深度的普通笔记，附件写入该笔记真实父目录的
`assets/<note-stem>/`，并从该目录计算相对链接；旧 Vault 根 bundle 保持可读。笔记移动后，
后续附件继续写入新的同级 bundle，不能重新分裂到 Vault 根目录。

## 退出与恢复

- 返回笔记列表前先处理未保存内容；不因返回而丢失输入。
- 强制结束后，已显示“已保存”的内容必须能够从 Vault 重新打开；未完成附件事务按 Vault 契约恢复或清理，不能留下一个已插入但不可访问的链接。
- 恢复到编辑器时优先恢复同一笔记与可用的阅读位置；无法恢复时解释原因并提供回到 Vault 或重新选择 Vault 的路径。

## 验收示例

- 输入中文、列表、链接和标签，停止输入后显示“已保存”，重启后内容逐字一致。
- 保存失败时继续输入，内容仍存在；恢复权限或空间后可成功保存。
- 拍照或视频插入后继续输入，链接位于原光标位置，电脑 Obsidian 可打开；点按视频链接时交由系统播放器打开。
- 字体放大、横屏和键盘打开时，保存、拍照及当前输入行仍可操作或可见。
